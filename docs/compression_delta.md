# Compression Delta: the Measured Cost of Using WhatsApp as the Transport

Generated by `R/07_compression_delta.R` on 2026-07-30 08:10. Both models trained/evaluated on the same source recordings and the same grouped train/val/test split -- the only difference is whether the test audio went through WhatsApp's Opus/Ogg compression before feature extraction.

Source-file sets for both conditions confirmed identical.

- **Compressed (WhatsApp-simulated) test accuracy: 86.9%** (23 test source files)
- **Uncompressed test accuracy: 86.6%** (23 test source files)
- **Delta (uncompressed minus compressed): -0.4%**

## Reading this number

A positive delta means compression cost accuracy (uncompressed did 
better); a delta near zero means the classifier's feature set is robust 
to WhatsApp's lossy encoding for these classes; a negative delta would 
mean the compressed model did *better* on its own held-out test set, 
which can happen with small test sets and should not be over-interpreted 
as compression *helping*.

## Interpretation

**Headline: a -0.4% delta -- WhatsApp's compression costs essentially
nothing on this feature set, for these classes.** The uncompressed model
does marginally *worse* than the compressed one on its own held-out test
set (86.6% vs. 86.9%), which is well within the noise of a 23-test-source-
file comparison and should not be read as "compression helps" -- read it
as "no detectable cost," full stop.

**This number was not clean on the first run, and getting it right
required fixing a real bug, not just reporting whatever came out.** The
first pass showed compressed at 86.9% and uncompressed at only 71% -- a
striking -15.9% delta that would have been a genuinely interesting
finding, except it was an artifact. Investigating *why* uncompressed did
so much worse found that `wa_features()`'s `harmonic_energy_ratio` returned
`NA` (not a real value) for any window with no well-defined peak frequency
-- which silently dropped the whole window from training/evaluation. Two
long, real recordings had many more such windows in the uncompressed
condition specifically: quiet stretches in genuinely uncompressed audio
stay genuinely quiet, while WhatsApp's own lossy noise-shaping incidentally
raises the noise floor just enough in the compressed condition to avoid a
literal zero-Hz peak. The result was that the uncompressed model's test
accuracy was being computed on a shrunken, unrepresentative slice of the
test set (100 usable windows vs. 221 for compressed, out of ~217-222
before dropping) -- not a fair comparison. Fixed `harmonic_energy_ratio`
to return 0 (a legitimate "no measurable harmonic structure" value) instead
of `NA` in that case (`pkg/whatsappaudioR/R/wa_features.R`, with a
regression test), re-ran both conditions, and the delta collapsed to
-0.4%. **The -15.9% number was never a real property of compression; it
was a data-completeness bug that happened to hit one condition much harder
than the other.** Recording this whole sequence here rather than only
reporting the clean final number, because "we found a striking number,
investigated it, and it turned out to be a bug" is itself the kind of
thing this project's whole approach is built on being honest about.

**What this does and doesn't tell us:** for the specific classes trained
here (3 real Orthoptera/Cicadidae species + real ambient + retained
synthetic comparison classes), using WhatsApp voice notes as the transport
does not measurably degrade this classifier's accuracy relative to
uncompressed audio at the same sample rate. This is consistent with, and
adds a classifier-level data point to, the codec experiment's own finding
(`docs/codec_findings.md`) that real Orthoptera stridulation survives the
16kHz/16kbps Opus round-trip well. It does **not** extend to the chewing-
sound classes (deliberately excluded from this classifier run -- see
`docs/methodology.md`), where the codec experiment found much poorer,
more variable survivability. It also doesn't say anything about audio
captured at greater distance, in wind/field noise, or through a real
phone microphone rather than these curated reference recordings --
those remain untested.

**Sample-size caveat:** 23 test source files is a small comparison base.
Treat "-0.4%, no detectable cost" as the honest read of this specific run,
not as a precise, low-variance estimate of the true population delta.
